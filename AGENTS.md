## Load-bearing boundaries

- METAPAT constrains terms, interpretations, derivations, and claim status.
- Every domain exposes some properties of Platonic energy; no domain exposes all.
- Domain implementations remain domain-specific unless a shared structure/action survives independent cross-domain reconstruction.
- Catalog v3 makes current doctrine addressable; it does not replace canon-bearing Markdown.
- Application modules bind domain uses to exact catalog identities and evidence boundaries; they do not validate the domain application.
- UCNS supplies actual representation/geometry through an optional adapter and retains authority over its theorem status.
- EDCM measures source evidence and retains authority over its measurements.
- Deterministic contract tests are not empirical or formal validation of METAPAT or an application.
- Source `CONTRACTS` own obligations; test `CHECKS` own executable evidence.
- Phi authorization supplies bounded semantic authority; it does not establish or inspect UCNS topology.

Do not restore the superseded single arrow `UCNS -> METAPAT -> EDCM`.

## Canon editing

- Consumers pinned to prior epochs reject v3 until explicitly migrated. Do not alias deprecated semantic IDs to new meanings.
- Unknown status is `hmmm`, not guessed closure.

## Semantic catalog

Use `canonical_semantic_catalog()` and exact module IDs rather than free-form reconstruction.

Catalog v3 is:

```text
1 root
12 axioms
7 postulates
8 theorems
12 theories
40 modules
43 exact derived-from relations
```

- Each module preserves exact source text, doctrine class, claim status, envelope provenance, ordinal, and module digest.
- Each relation preserves exact endpoints, relation kind, evidence status, source text, unresolved constraints, and relation digest.
- Postulates are `WORKING-POSTULATE`, not root or theorem.
- Current theories are `INTERNAL-DERIVATION`; domain applications carry their own bounded application status.
- Addressability does not transfer claim status into an application, UCNS object, EDCM value, or downstream proof.
- Catalog relations reproduce declared ancestry only; do not infer edges from analogy, repeated words, order, geometry, carrier size, or symmetry.
- Ordinary catalog construction rejects `constitutive-simultaneous` relations without explicit Phi authorization.
- `fixtures/semantic-module-catalog-v3.json` must equal the live catalog constructor plus one trailing newline.

## Application modules

Use `MetapatApplicationModule` only for domain applications with exact source documents and explicit evidence boundaries.

- Bind applied terms through `ApplicationCatalogBinding` to exact current catalog IDs/digests/statuses.
- Preserve application status as `CROSS-DOMAIN-HYPOTHESIS` or `EMPIRICAL-FRONTIER`; never inherit root/theorem status.
- Preserve domains, transfers, non-transfers, evidence requirements, and unresolved `hmmm`.
- Keep root impact and all METAPAT/domain/measurement/theorem-transfer/UCNS-topology validity fields false unless separately established by the owning domain.
- Catalog rotation invalidates stale application fixtures rather than silently rebinding them.
- Successful serialization, fixture identity, semantic resonance, or passing contract tests do not validate an application.

## UCNS adapter and Phi policy

`src/metapat/ucns.py` contains no local UCNS algebra.

- Base import works without UCNS installed.
- Construct only actual UCNS objects through the actual dependency.
- Retain the complete semantic envelope in the adaptation record.
- Default mapping is `external-provenance`; payloads remain UCNS-owned.
- Never transfer theorem or validity status.

`src/metapat/ucns_phi.py` owns semantic authorization policy only:

- fork mode is explicit authorization only;
- current authorized relation is `constitutive-simultaneous`;
- authorization never establishes METAPAT validity, UCNS topology, or EDCM measurement validity;
- downstream integration must bind exact UCNS identities/topology independently.
