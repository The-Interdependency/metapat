# Domain Restraint Doctrine

Energy Theory is a magpie, not a mimic.

It may learn from any domain.

It may not surrender its root to any domain.

## Rule

```text
Different domains may independently expose common structures and actions.
Domains may clarify the root.
Domains may not redefine the root.
Structural resemblance does not transfer a domain term, mechanism, evidence standard, or conservation law.
A domain term applies only where that domain independently licenses it.
```

## Root-protection test

A proposed term, formula, metaphor, component, or example may enter METAPAT only if it passes all of these checks:

1. It clarifies a root or derived term.
2. It does not require its source domain to be true everywhere.
3. It states what transfers and what remains domain-specific.
4. It survives comparison with implementations from other domains.
5. It remains demotable if a later domain falsifies or splits the candidate.
6. It does not transfer a source-domain name merely because the target domain shares a structure.

## Domain capture failures

Reject or demote a proposal when it does any of the following:

- Calls every state transformation `energy` because energetic systems also contain state, vectors, transformation, and time.
- Makes an electrical component a universal operator because one circuit implements it clearly.
- Makes mechanical motion the parent ontology because mechanics exposes constraint and trajectory well.
- Makes mathematical scalar, vector, matrix, or tensor notation own the METAPAT terms.
- Makes geometry the definition of relate merely because geometry is one relation.
- Makes language own context, questions, or registration because language exposes them clearly.
- Makes accounting balance a universal conservation law because double entry preserves a domain invariant.
- Makes consciousness the creator of boundary, state, transformation, or time.

## Correct import pattern

Use this form:

```text
Domain implementation: <thing or formalism>
Clarifies: <METAPAT structure or action>
Transfers: <operation or structure that survives domain removal>
Does not transfer: <domain-specific name, mechanism, law, evidence standard, or implementation>
Root impact: none unless separately falsified and amended
```

## Example: storage

```text
Electrical implementation: capacitor / battery
Mechanical implementation: flywheel
Linguistic implementation: written language
Candidate transfer: preserved state made available later
Does not transfer: voltage, chemistry, rotation, words, or any other domain-specific mechanism
Root impact: none
```

## Example: relation

```text
Geometric implementation: position, distance, orientation, intersection
Semantic implementation: meaning relation
Logical implementation: implication or dependency
Candidate transfer: this to that
Does not transfer: geometry, semantics, or logic as universal parent ontology
Root impact: none
```

## Example: accounting adversary

```text
Accounting implementation: double-entry posting across at least two accounts
Candidate transfer: related, measurable state transformation under a domain invariant
Does not transfer: debit/credit terminology, accounting equation, monetary meaning, or the name energy
Root impact: falsifies universal transfer of energy as a cross-domain name
```

## hmmm

Cross-domain recurrence is evidence for a candidate structure, not proof of universality, completeness, or semantic identity.
